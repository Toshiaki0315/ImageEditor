## Claude Code への指示の出し方

リポジトリ直下で `claude` を起動する。`CLAUDE.md` は自動で読み込まれるので、`/read` などで読ませる必要はない。

### 基本形（1 Issue ずつ）

```
/issue 1
```

`.claude/commands/issue.md` のカスタムコマンドが、Issue の確認 → ブランチ作成 → 実装 → テスト → PR 作成までを行う。PR をレビューして自分でマージしたら次の番号へ。

### コマンドを使わない場合のプロンプト例

```
GitHub Issue #4 を実装してください。
gh issue view 4 で受け入れ条件を確認し、CLAUDE.md のワークフローに従って
ブランチ作成・実装・テスト・PR 作成まで行ってください。マージはしないでください。
```

### 着手前に計画だけ見たいとき

Shift+Tab でプランモードに切り替えてから `/issue 7` を実行すると、コードを書く前に実装方針を提示させられる。UI 系の Issue（#7〜#9）ではおすすめ。

### うまくいかないとき

- テストが通らない → 「pytest の失敗を読んで原因を説明してから直して」
- 仕様の解釈が分かれた → Claude に質問させ、決めた内容を `docs/requirements.md` に追記させる
- 見た目の調整 → スクリーンショットを貼って「この部分の余白を詰めて」のように指示する
